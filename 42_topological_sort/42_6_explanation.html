Questions About 42_6_longest_path_of_increasing_degrees.py

The key idea of this file is: start from an undirected graph, then give each edge a direction from smaller degree to larger degree.

After that, the code treats the result like a DAG and computes the longest path.

1. What does dag_neighbors do?

def dag_neighbors(graph, node):
    return [nbr for nbr in graph[node] if len(graph[nbr]) > len(graph[node])]

It returns only the neighbors whose degree is strictly larger than the current node's degree.

So if node u is connected to node v, then:

  • if degree(v) > degree(u), keep the direction u -> v
  • otherwise, do not include v in dag_neighbors(u)

In other words, dag_neighbors builds the "forward edges" of the DAG.

Read this left to right. The original graph has edge u - v. Since degree(v) > degree(u), the algorithm keeps only the forward direction u -> v.

Circle: a node in the graph

Line without arrow: original undirected edge

Arrow: edge kept by dag_neighbors

Colors: only for visual separation; the meaning comes from the text labels, not from color

Why is this needed?

The original graph is undirected, so it may contain cycles. Longest path is hard in a general cyclic graph.

But if we only move from lower degree to higher degree, degrees must keep increasing along the path: 

degree(a) < degree(b) < degree(c) < ...

That means you can never come back to an earlier node, because coming back would force the degrees to go down again. So this orientation removes cycles and gives a DAG-like direction to the graph.

Then topological sort and dynamic programming become possible.

Small example

Suppose:

  • degree(0) = 1
  • degree(1) = 3
  • degree(2) = 4

If the undirected edges are 0-1 and 1-2, then:

  • dag_neighbors(0) = [1]
  • dag_neighbors(1) = [2]
  • dag_neighbors(2) = []

So the code effectively turns the graph into: 

0 -> 1 -> 2

Important: this path is allowed because each next node has a larger degree than the previous one.

Why no backward arrow? Going from 2 back to 1 would decrease degree, so the algorithm does not keep that direction.

2. Why does if lengths[node] + 1 > lengths[nbr] work?

if lengths[node] + 1 > lengths[nbr]:
    lengths[nbr] = lengths[node] + 1

lengths[x] means: the longest increasing-degree path found so far that ends at node x.

If there is an edge node -> nbr, then any path ending at node can be extended by one more edge to reach nbr. So the new candidate length is: 

lengths[node] + 1

The condition checks whether this new path is better than the best path currently known for nbr.

  • if it is bigger, update lengths[nbr]
  • if it is not bigger, keep the old value

This is standard dynamic programming: for each node, keep the best answer seen so far.

This diagram is about the single line if lengths[node] + 1 > lengths[nbr]. The algorithm tests a new candidate path, compares it with the old best answer for nbr, and keeps the larger one.

lengths[1] = 2: the best path ending at node 1 currently has length 2

+ 1: one more edge is added when moving from the current node to its neighbor

Comparison: if the new candidate is larger, update; otherwise leave the old value unchanged

Colors: the top and bottom arrows use different colors only to separate the two candidate paths

Example for the condition

Suppose we already know:

  • lengths[1] = 2
  • lengths[3] = 1
  • both 1 and 3 have an edge to 5

Then from node 1, we can make a path to 5 of length 3. From node 3, we can make a path to 5 of length 2. 

from 1: lengths[1] + 1 = 3
from 3: lengths[3] + 1 = 2

We should keep the better one, so lengths[5] should become 3, not 2. That is exactly why the condition uses >.

Short summary

  • dag_neighbors keeps only edges that go from lower degree to higher degree.
  • This is needed so the undirected graph can be treated like a DAG.
  • lengths[node] + 1 means "extend the best path to node by one edge".
  • The > check means "only update if this gives a better path for nbr".

One subtle point: if two adjacent nodes have the same degree, this code ignores that edge because it uses a strict >.
